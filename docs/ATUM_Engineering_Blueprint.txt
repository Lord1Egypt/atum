ATUM
The complete AI market simulation laboratory
Virtual markets. Artificial agents. Measurable intelligence.
Architecture vision, repository gap assessment, capability catalogue, implementation roadmap and acceptance
gates.

Mission
Give every AI research agent a complete virtual dealing room: its own synthetic account, a consistent market
clock, evidence-backed analysis, an instrumented workstation, a reproducible simulator, and an independent
evaluator. Every order, balance and result stays fictional. No real money, broker access, deposits, withdrawals or
production order routes are in scope.

never the source of truth for account balances.

    Research gateway

    Simulation kernel

    Market data plane

    Observability

Execution boundary
Agent request → policy gateway → simulation command queue → deterministic state transition → journal →
read projections → evaluation. No direct agent mutation of database, clock, balance, dataset or evaluator. All
commands carry run ID, virtual account ID, identity, schema version and idempotency key.

Proposed module boundaries
Extend internal/adapter/simulation into a single authoritative simulator; isolate domain types in internal/sim;
create internal/dataset for provenance, internal/experiment for orchestration, internal/evaluation for metrics
and internal/researchtools for the scoped tool surface. Keep legacy adapters outside the demo distribution.
Preserve existing APIs with versioned compatibility views where safe.

Engineering invariants
      Same immutable data, configuration and scripted inputs produce equivalent ledger and event hashes.
      Every output has a provenance record and explicit simulated status. Missing inputs cannot silently become
       zero or random values.
      A failed event cannot partially mutate balance, orders or positions. UI and AI read from committed
       projections.

DESIGN MODULE / 03


Virtual accounts & accounting
The simulator is a fictional financial system; its correctness is an accounting problem before it is an AI problem.

Account lifecycle
      Create, list, inspect, pause, snapshot, reset by new run, clone a baseline and archive. Every account belongs
       to one experiment and has a unique identity, virtual base currency and initial synthetic balance.
      Store cash, reserved cash, holdings, liabilities, realized/unrealized P&L and equity as distinct fields. Label all
       amounts SIMULATED; forbid real deposits, withdrawals and external transfers.
      Use fixed-point decimal or integer units with instrument-specific rounding. Validate finite positive quantity
       and price, currency precision, minimum increments and maximum synthetic bounds.

Journal model
    Record                                                     Minimum fields

                                                               account_id, run_id, base_currency, status, created_at,
    Account
                                                               initial_cash

                                                               instrument_id, asset class, quote currency, tick size,
    Instrument
                                                               quantity increment, contract metadata

                                                               entry_id, transaction_id, account_id, asset, signed amount,
    Ledger entry
                                                               cause, sequence

                                                               order_id, idempotency_key, simulated state, timestamps,
    Order / fill
                                                               quantity, price, fees

                                                               account_id, event sequence, balance, positions, equity,
    Snapshot
                                                               digest

                                                               dataset digest, scenario, seed, clock, config, code revision,
    Run
                                                               agent identifier


Verification contracts
      A fictional spot sale with no holdings fails without changing cash. Oversells and negative quantities fail
       atomically.
      Buy/sell round trips reconcile cash, holdings, fees and reported realized P&L; no hidden creation of virtual
       funds.
      Duplicate request, retry, restart and concurrent account access yield exactly one committed transition.
      Derivatives and multi-currency accounting remain disabled until their fictional contract and valuation
       invariants are tested.

Virtual lifecycle and clock
Model submitted, accepted, pending, partially filled, filled, cancelled, rejected and expired as explicit states.
Distinguish observed time, availability time, event time and processing time. Keep stable ordering for equal
timestamps. Use explicit simulation clock injection rather than wall-clock time in deterministic runs.

Fidelity and adversarial fixtures
      Validate fictional limit eligibility, price gaps, market closures, quote staleness, partial fills and cancellation
       races. Treat uncertain intrabar paths conservatively or mark them ambiguous.
      Model fees, spread, rounding and latency as scenario parameters with provenance, not unverified broker
       guarantees. Document which parameters are measured, synthetic or unavailable.
      Test missing and duplicate events, out-of-order timestamps, zero liquidity, split sessions, abrupt jumps,
       disconnects, restart, extreme values and capacity exhaustion.
      Do not enable asset classes that lack an adequate contract model. Validate equity, cost and state transitions
       against independent hand-calculated fixtures.

Common kernel rule
Historical replay and interactive paper experiments must share the same state transition and accounting
implementation. The backtest driver changes the clock and dataset, not financial semantics.

Data ingestion and governance
        Provider registry: import CSV/Parquet, fixture generator and optional approved read-only feeds. Validate
         schema, time zone, monotonically ordered keys, duplicate policy, gaps, units and source rights.
        Store immutable raw snapshots and normalized partitions; manifest includes source, retrieval time, time
         range, instrument metadata version, checksum, transformation version and quality flags.
        Expose as-of queries with explicit availability timestamps to prevent future data leakage; cache by dataset
         version, not mutable symbol alone.
        Never fill unavailable market observations with random numbers disguised as live data. Separate missing,
         delayed, stale, estimated and synthetic states.
        Local-first default: small indexed SQLite metadata and columnar dataset files; compressed partitions,
         retention limits, export and checksum verification.

Market workstation
Provide a watchlist, multi-timeframe charts, session clock, dataset coverage, price freshness, market calendar,
historical event browser and an instrument inspector. All panels indicate the source and replay timestamp.

Canonical computation contract
Every indicator declares inputs, parameters, formula version, minimum lookback, warm-up behavior, timestamp
convention, output units and validity. Return missing with reason rather than a numerical zero when data is
insufficient. Use one implementation across API, chart and research runtime; remove duplicate helper drift.

Validation and pattern analysis
Compare against independent reference vectors, hand calculations and randomized property tests. Test constant
prices, short series, nulls, extreme values and split adjustments. For subjective patterns (Elliott, ICT/SMC, chart
formations), publish formal definitions, ambiguity and negative examples; no claims of predictive power without
holdout evidence.

Tool protocol
Use versioned JSON schemas and machine-readable errors; output includes source, as_of, run_id,
simulated=true, quality flags and trace ID. Provide read tools first, enforce permissions server-side, and prohibit
unrestricted shell, external execution APIs and secret retrieval. Agent output is untrusted data. Record concise
decision summaries and tool traces, not private reasoning.

Human interface
Dashboard: experiment overview, account explorer, chart grid, data inspector, indicator overlays, alerts inbox,
notebook, run comparison, event timeline, failure archive and export. Provide searchable commands, keyboard
access, dark/light themes, accessible contrast and clear demo watermark. Use a deterministic scripted agent as
the reference client before testing LLM integrations.

Experiment science & AI evaluation
The goal is reliable comparisons and falsifiable hypotheses, not maximizing a leaderboard or promoting a
winning model to real markets.

Experiment design
      Register hypothesis, immutable dataset, time window, seed, baseline, scenario, agent/model identifier,
       model parameters, tool versions and budget before each run.
      Separate chronological train, validation and untouched test windows; use point-in-time data; report
       selection bias, multiple comparisons, survivorship bias and leakage checks.
      Compare identical datasets and constraints using independent virtual accounts. Repeat with multiple seeds
       or scripted replay; distinguish stochastic model variability from deterministic simulator behavior.
      Include no-action, simple scripted and random baselines with declared seeds. Preserve failed runs and show
       confidence intervals or uncertainty where appropriate.

Metrics and evidence
    Metric family                                          Required reporting

                                                           Ledger reconciliation, state transition violations, replay
    Simulator correctness

                                                           exposure.

    Statistical reliability
                                                           baseline comparison, sensitivity and failure cases.

                                                           Tool-call count, schema errors, abstention, unsupported
    Agent behavior
                                                           claims, latency, cost, policy violations and reproducibility.

                                                           CPU/RAM, dataset throughput, queue depth, recovery
    Operational quality

ATUM Launch Control
Software-only lifecycle: candidate → sandboxed → evaluated → qualified for further simulation or quarantined
→ archived. A failed agent receives an immutable failure dossier with trace IDs, seeds, regression cases and
remediation notes. No automatic promotion to external markets. The only launch is a simulated research run.

Safety, security & operations
Make demo-only a system invariant enforced independently of the UI, model and configuration.

Isolation and controls
      Remove or compile out live-execution code paths from the demo artifact. No broker keys, wallets, live API
       trading, payment integrations or external account creation. Deny outbound connections except explicitly
       approved read-only data/model endpoints; default offline fixture mode.
      Bind to loopback by default; use authenticated per-run scoped tokens, least privilege, input validation, safe
       path resolution, request limits and separate admin/agent roles. Redact secrets and sensitive data from logs.
      No unreviewed third-party plugins or executable downloads. Isolate untrusted research plugins, constrain
       CPU/RAM/time, and deny host filesystem/network access by default. Treat external content as untrusted.
      Use transaction boundaries, append-only event journal, snapshots, migration backups, integrity checks and
       crash recovery. Prefer SQLite single-writer ownership and bounded queues; measure before scaling out.

Proposed initial acceptance workload (not measured)
Start with 10 independent virtual accounts and a common immutable fixture; verify that account activity cannot
alter another account or the shared market dataset. Run repeated replay and restart scenarios; measure
p50/p95 latency, peak RSS, throughput and disk usage on the target machine. Expand concurrency only after
recording a baseline. No arbitrary performance promise.

Stop conditions
Block release for any broken conservation invariant, look-ahead leak, cross-account state access, non-demo
route, silent data fabrication, unsupported capability claim or unreconciled replay. Preserve logs and report
failure rather than bypassing a gate.

Engineering handoff & evidence
This document is a proposed roadmap, not an implementation report. Use it to derive issues and bounded pull
requests.

Instructions for the engineering agent
Begin by reading the repository, verifying the pinned tree and mapping each requirement to existing code and
tests. Keep architecture and working interfaces unless evidence justifies change. Work in small reviewable
commits. Do not implement or enable real-money execution. Prioritize P0 correctness; avoid feature expansion
until the simulator is reliable. For each phase, deliver a diff, test commands and output, fixture hashes, migration
notes, known limitations and an explicit pass/fail verdict. Never replace unavailable data with fabricated
observations or claim profitability from simulation.
